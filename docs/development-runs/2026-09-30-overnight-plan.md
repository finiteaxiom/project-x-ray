### 1. 高风险候选：发现时的路径检查与后续打开之间可能发生逃逸

- **确认的代码事实：** `discoverProject` 对枚举到的路径执行 `realpath` 和根目录包含性检查，然后把路径字符串放入 `files`；索引器稍后直接 `readFile(absolutePath)`。同样的“发现后按路径读取”也出现在一致性复读和 Git 工作区捕获中。
- **依据：** `packages/analyzer-core/src/index.ts:100-104`；`packages/application/src/index.ts:79-88,357-359`；`packages/git/src/index.ts:100-104`。
- **影响假设：** 若目录项或父目录在检查和打开之间被替换为指向根外的符号链接/目录联接，后续按路径打开可能读到根外文件。此次只确认检查与打开分离，未复现竞态，也未证明有数据已进入快照。
- **预期行为：** 被导入或比较的每个字节都必须来自导入根目录内经校验的对象；路径在校验后发生变化时应安全失败，不得把根外内容交给分析器、持久化或 Git 比较。
- **最小修复边界：** 为索引初读、快照一致性复读和 Git 工作区捕获共用安全读取边界，使校验与打开绑定到同一文件对象，或对打开后的对象身份及根目录包含性作可靠校验；保留现有快照指纹检查。不要只在 `readFile` 前再校验一次路径字符串。
- **建议的最小复现/验证（未执行）：** 在发现完成与文件打开之间设置确定性同步点，将已发现文件替换为指向根外哨兵文件的符号链接或目录联接；断言哨兵内容从未交给分析器/捕获流程且不会发布快照或比较结果。优先使用可控临时目录，不执行样例仓库代码；若 Windows 联接创建受权限限制，应记录环境限制并选择可用的受控路径替换机制，不以无竞态的普通测试代替。
