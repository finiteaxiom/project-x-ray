# V1 可信索引与源码导航修复

## 目标

修复第一批审查确认的索引与证据缺陷：嵌套同名符号身份、Python 局部绑定边界、隐藏源码发现、普通/Git 源码范围一致性与文件源码导航。保持 V1、本地优先、静态证据与置信度边界，不执行被索引项目的代码。

## 确认的失败与根因

- TypeScript 样例里两个不同外层函数的 `helper` 被合并为一个节点。根因是限定名和节点 ID 未包含词法所有者；相同局部名因此冲突。
- Python `for` 目标遗漏于函数局部绑定收集，遮蔽调用被错标为已验证；装饰器替换函数名后仍把调用指向原定义。根因是作用域扫描不覆盖循环/异常绑定、推导式自身作用域和装饰器重绑定。
- 隐藏目录源码样例起初发现 0 个源文件。根因是 glob 默认跳过点路径，秘密文件尚未进入后续分类策略。
- 普通索引多行文件的范围结束列为 0，而 Git 比较侧依据末行计算。根因是普通索引使用固定的零结束列，未使用内容的真实末行长度。
- 首次 Electron E2E 中，非空文件可打开，但 `source-viewer` 没有文件证据 ID；证据范围为空的空文件读取失败。根因是 App 的文件节点导航只传 span，而文件节点与其已有 `kind=file` 证据之间没有直接链接。
- 新增 Git 侧断言一度把 `report.right.snapshot`（仅含仓库/快照 ID 的引用）当作完整快照读取，触发测试代码 `Cannot read properties of undefined (reading 'find')`。这是回归测试写错读取边界，不是产品缺陷；改为通过应用搜索接口读取该侧文件节点后通过。
- Git 比较用例在隔离运行约 2.13 秒，全仓默认并行及并发 4 时约 4.67 秒，接近原 Vitest 5 秒门限；并发 2 的强制全仓运行将该用例降至约 3.13 秒。根因是 Windows 全仓并行负载与 Git 子进程争用，判定为测试运行资源问题，不是 Git 产品缺陷。根脚本设为 Turbo 并发 2；没有改超时或减断言。

## 修改

- TypeScript 声明限定名和稳定 ID 纳入词法所有者，分析器版本升为 `${ts.version}+xray.3`；回归覆盖两组嵌套同名 helper 的节点、owner 定义边、调用目标及来源范围。
- Python 作用域收集控制流体中的绑定并隔离推导式作用域；装饰器函数及其导入调用不再错误解析为原始定义，原因和证据置信保持 `unknown`。Python worker 协议和分析器版本升为 `2.1.0`；回归保留未装饰安全调用的 `verified` 正向例。
- 目录扫描使用 `dot: true`，仍不跟随符号链接并显式跳过秘密/构建/供应商目录；索引测试验证隐藏源码和排除清单。
- 普通索引和 Git 比较两侧都由实际内容生成完整文件范围；允许空文件仅在精确的 `1:0–1:0`、匹配的同快照 `kind=file` 证据下读取，不能把零宽范围当作答题引用。
- Graph IR 升为 `1.3.0`，文件节点显式引用自身文件证据；架构源码导航将该 ID 传入 `readSource`。新增真实 Electron E2E，导入临时夹具并验证单行、多行、emoji UTF-16 列、空文件、隐藏源码检索，以及秘密/构建/依赖文件未进入索引。旧 Graph IR 快照不被静默改写，重新索引后才带有节点证据 ID。
