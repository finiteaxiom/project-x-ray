## 当前判断

本轮只读核对了最新开发记录、索引编排、分析器入口和 UI 构建配置，未重跑产品测试。UI 收尾验证属于已有开发记录。索引仍调用 TS/Python 的项目级分析入口；快照身份包含源码、配置、Graph IR 和分析器版本；前端已有部分 Monaco 延迟加载，不能假设它完全没有懒加载。

下一阶段重点：让已可操作的六页工作流，在重复索引、复杂源码和启动加载上更可靠。今天安排三个独立长任务，分别负责后端索引复用、语言事实可信度和前端加载性能。Git 报告分页涉及契约、应用、持久化和 UI，放在这三项集成之后串行推进；远程 LLM 授权与 Windows 安装生命周期也单独安排，避免在一次并行批次中同时扩大多个边界。

## 开始前：共同基线

主 checkout 仍有 UI/CSS 收尾的未提交改动。创建开发 worktree 前，应先将已验收代码、本轮 AGENTS.md 新规则及本计划保存为共同基线提交，或明确使用应用提供的“包含当前本地改动”的起始方式，并核对三个 worktree 实际收到同样的文件。不要默认新 worktree 自带主目录未提交文件。

每个任务一个独立 worktree，不要让三个任务都运行在原项目目录。不要共享可写 node_modules、dist、数据库、Electron userData 或 fixture 临时目录。pnpm 自身的正常内容寻址存储可沿用，但不通过目录联接共享会被构建或 native rebuild 修改的安装目录。

准备阶段记录 HEAD、实际工作目录及初始 git status。HEAD 相同但本地补丁不同不算同一基线。AGENTS.md 和本计划缺失时，应报告基线问题，不开始实现。

- 保留键盘焦点、源码选区与滚动位置、分栏偏好和已经修复的 disabled 状态。
