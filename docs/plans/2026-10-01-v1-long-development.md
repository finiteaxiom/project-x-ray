## 推进与状态规则

每批拆成可独立交付的小切片：设计审查 → 实现 → 开发方定向验证 → 冻结交付 → 协调方差异/回归/真实 Electron 验收 → 集成复验 → 提交推送。不等待整个聊天永久结束；以明确稳定文件边界为准。重型构建、原生编译和 Electron 验收只有一个协调窗口。

队列使用：待设计、设计中、实现中、已交付待审、修正中、已验收、外部阻碍、用户跳过。测试替身、真实 Electron、本机 OS 凭据存储、真实远程服务分别记录，不合并为“全通过”。批次仅在必需门槛满足后关闭；有外部阻碍时可并行开展不依赖该门槛的后续准备，但不能把受阻批次标为已验收。

每轮有意义的实现/验证/失败诊断/修正/再验证写入 development-runs。AGENTS 只收录符合证据、适用、可执行、查重及记录链接门槛的经验，允许无新增。协调方集成逐条规则，不覆盖整份 AGENTS。开发聊天不自行 Git 收尾。

## 第一批：受证据约束的 AI 解释

目标：从当前快照查询功能证据，生成有引用的解释；保留离线模板，随后以相同证据适配架构职责标签。LLM 叙述保持 inferred，既有语法事实的 verified 不因叙述改变。模型不得创建图事实。

1. Sol 先提交最小设计及文件清单：独立 llm 层、证据包/响应版本、项目授权与撤销、Windows OS 凭据存储、任务身份/取消/预算、快照与配置修订核验、UI/IPC 契约。设计审查后实施，不先写跨层代码。
2. Luna 同时准备小型自建金标/对抗样例和交互验收清单，仅自己的新增样例及记录；在契约冻结并进入主 checkout 后，再派发 UI 实现。第一轮不修改 Sol 所需的共享契约、desktop、application、package/lock 或全局样式。
3. 首个适配器沿用已批准架构的 OpenAI Responses API。优先平台 fetch 与现有 Zod，新增依赖须论证。模型 ID 显式配置且不假定账户有某模型。HTTPS 固定官方主机，禁止自动重定向或任意端点把凭据发到别处；不启用仓库执行、网络工具或文件系统工具。
4. 最小证据按实际范围裁剪，包含快照/来源和截断信息；限制输入体积、输出 token、响应体积、耗时与并发；不自动循环付费重试。显示数据类别、查询及限额，远程失败仍可用本地证据。
5. `store:false`、结构化输出 `text.format`；不把它描述为服务商零保留。拒绝不存在/错项目/错快照/超出证据包的引用、模型 refusal、incomplete、无引用结论、无效 JSON。保留 unknown 与真实静态路径限制。

验收：本地模板兼容；授权前零网络调用、撤销/项目切换/源码或排除配置变化期间迟到结果拒绝；提示词注入不提升权限；错误不泄露源码或凭据；Windows 凭据写入/读取/删除及重启；实际 Electron 解释→源码导航、取消、失败与恢复、架构引用标签。网络协议替身测试不能替代真实服务调用，真实调用单独登记。

官方资料核对于 2026-10-01：[Responses](https://developers.openai.com/api/docs/guides/migrate-to-responses)、[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[数据控制](https://developers.openai.com/api/docs/guides/your-data)。实现时开发方再次核对适用接口，不从文档导航标题猜测模型可用性。

## 第二批：所有权语义评价

依赖：第一批可信证据包/提供商接口与隐私、任务身份边界稳定。先修订/新增 ADR，明确 ADR-0006 的离线自由文本“未评估”继续成立；只在显式启用远程评价时增加语义维度。

Sol 负责证据约束 rubric、评分/尝试版本、后台校验与追加持久化；Luna 在接口冻结后负责答题/引用/等待/评价/复习界面。模型不改确定性定位及结构分数；语义不能仅比较关键词、不能掩盖缺证据。模型不可用、无证据、输出无效或证据变化时保持未评估/不可评分，不能形成假掌握。

验收：正确引用但错误解释、正确解释但无引用、重复/错快照引用、注入答案、反例与模型不一致输出；提交前不泄露答案；取消/重试无重复写入；快照改变后掌握失效；实际 Electron 完整答题与补救路径。固定 rubric 金标与真实远程小样例分别报告，不能声称模型在所有项目上可靠。

## 第三批：增量索引与性能

Sol 先测量当前全量索引/查询/内存基线，设计按语言的保守失效边界；跨文件导入、TS 配置和 Python 绑定不能按单文件哈希盲目复用。Luna 可并行维护自建样例/基准工具及进度交互，文件清单须先冻结。

以安全重用不可变文件/解析产物开始；无法证明局部失效正确时回退对应语言或全量分析。配置、分析器版本、依赖解析环境、缺工具→恢复及 Git 双侧变化必须参与缓存身份。当前发布事务及历史快照不可变规则不变。

验收：增量与干净全量规范化事实/源码/证据一致，覆盖修改/新增/删除/重命名、导入别名/循环、跨文件调用、解析失败恢复、忽略策略、取消、并发写入与 A→B→A 重启。先做普通索引，再单独评估 Git 两侧复用；查询分页/缓存只按实测瓶颈派发。报告硬件/规模/冷暖运行及正确性，不能将单样例数据外推全部项目。实际 Electron 索引→变更→过期→更新→导航/旧快照验证。

## 第四批：Windows 发布

依赖：本轮功能集成稳定。Luna 负责已有 electron-builder 基础上的 per-user 安装器、portable、版本/产物校验和安装/卸载说明；Sol 按需负责数据库升级兼容及复杂数据生命周期。先验证现有依赖能满足，不引入新服务。

明确 Python/Git 的外部依赖策略，暂不自动捆绑/下载。定义默认保留用户数据、显式删除确认和凭据清理规则；不对用户实际应用数据做破坏性安装试验。使用可隔离的测试应用标识/测试数据做本机安装→启动→升级→重启→卸载测试，实际原生 UI 验证。旧版本数据库保留备份与兼容边界，不使用 reset/删用户数据修复失败。

签名方案、证书来源与费用先形成可审查方案；没有证书时可以交付明确 NotSigned 的测试产物，Authenticode 签名和正式可信发布保持外部阻碍，不伪造完成。使用 GitHub 发布或上传二进制前核对当前范围及实际目标；本计划默认只做 Git 交付及本地产物，不自动公开发布。干净机器验收仍为用户跳过。
