# ADR 0003：按快照绑定的有预算证据图查询

## 状态

已接受并在 V1 实现。

## 背景

把整份 `ProjectSnapshot` 发送到渲染进程，会把仓库规模直接转化为启动、IPC、布局和交互成本。旧流程查询还会双向扫描全部边，并把包含、定义、调用和数据关系混在同一张图中；这既不可控，也容易把普通可达性误写成执行或数据流证明。

## 决策

- `Graph Query 1.0.0` 请求必须绑定项目和快照，并声明根节点、视图、方向、深度、节点/边/内部工作量预算与置信度过滤。
- 调用视图默认仅含 `HANDLES`、`CALLS`；数据视图仅含 `READS`、`WRITES`、`RETURNS`、`PASSES_TO`；依赖视图仅含 `IMPORTS`、`DEPENDS_ON`。
- SQLite 规范化表是新交互主路径的数据源。项目概览、模块、搜索、子图、证据和源码分别按需读取；兼容用完整快照 JSON 暂时保留。
- 遍历按稳定顺序进行，对循环用已访问节点和边去重。未知目标节点和 `unresolvedTarget` 必须返回。
- 截断必须返回原因、统计和继续游标。游标包含查询哈希与快照 ID，不能跨查询或跨快照复用。
- UI 用请求序号丢弃迟到结果；查询运行在后台 worker 中，主事件循环不执行遍历或布局。
- 模块仅表示目录分组。聚合关系保留底层边、证据数量及置信度构成，不把混合置信度提升为 `verified`。

## 坐标契约

源码范围使用 1 基行号、0 基 UTF-16 列号和半开区间 `[start, end)`，与 TypeScript 和 Monaco 对齐。Python `ast` 返回的 UTF-8 字节列在分析器边界转换为 UTF-16 列。引用验证同时检查起止顺序、两端列边界和二维半开区间重叠。

## 快照校验

状态检查和发布前验证都使用相同发现/忽略规则重新发现文件，再比较规范化路径与内容哈希，因此新增、删除、重命名、支持配置变化和索引期间变化都会被识别。配置身份范围为 `package.json`、`pyproject.toml`、`requirements.txt`、`tsconfig.json`、`jsconfig.json`；不解析外部 `extends` 或工具隐式配置。

普通文件系统不提供跨多文件原子读取。本实现只承诺“首次发现/读取 + 发布前重新发现/读取”两次一致性校验；第二次校验后、事务提交前的极短并发修改仍是已知限制。历史不可变源码是否可读与工作区是否当前分别表达。

## 后果

- 大项目重新打开和搜索不再需要反序列化或传输整图。
- 功能解释只从有界调用查询生成有限静态路径；数据关系不再拼接为顺序故事。
- SQLite 迁移版本升至 3，新增小型概览表与查询索引；旧快照在首次读取概览时兼容回填，不删除旧数据库。
- 继续游标包含已访问集合，受契约长度和单次结果规模限制；它适合 V1 交互探索，不是无限图流协议。
