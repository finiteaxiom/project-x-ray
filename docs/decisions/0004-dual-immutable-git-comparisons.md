# ADR 0004：双侧不可变 Git 比较与有界影响路径

状态：已接受并实现  
日期：2026-09-20

## 背景

旧实现把当前索引图与一段文本 diff 组合，无法证明删除侧源码、index blob、历史配置和影响边来自同一版本，也无法在仓库继续变化后可靠复核报告。

## 决策

- `ChangeSet 1.1.0` 同时保存用户选择的模式、实际解析后的左右来源、内容与清单指纹、分析身份、分析完整性、查询预算和左右快照引用。兼容读取 `1.0.0` 时必须降级为 `partial`，不能假定旧报告完整。
- 工作区比较为 index → working tree，暂存区比较为 HEAD → index，最近提交为明确选择的父提交 → HEAD；初始提交使用 Git 空树，合并提交必须指定父序号。
- commit 通过 Git 对象读取，index 读取 stage 0 的实际 blob，working tree 使用项目发现与安全规则读取。两侧均建立完整的、不可变源码快照；比较侧快照可浏览但不会成为项目 current。
- 工作区身份包含实际纳入分析的受支持源码/配置路径及内容哈希，因此未跟踪文件在名称和状态不变时的内容变化仍会使报告过期。秘密、忽略、不支持、二进制和超限内容不读取正文；只保存允许的分类元数据，其正文变化不属于报告身份。
- 捕获前后核验 HEAD、index 与相关工作区内容身份；变化时只进行一次有界重试，仍不稳定则不发布报告。两侧分析和影响计算结束后再核验一次并以当时的 `current/stale/missing` 状态发布；此后 UI 状态检查继续独立核验。普通文件系统上最后一次核验后的极短竞态窗口仍存在。
- 文件状态与 patch 使用同一套比较参数、同一次完整 diff 捕获和相同的重命名阈值。需要限定路径时只使用 `:(literal)` pathspec；不会把方括号、星号或 pathspec magic 当成模式。
- 空树对象由当前仓库对象格式生成；SHA-1 与 SHA-256 仓库均按实际对象长度校验。初始提交与尚无提交的仓库分开处理，后者明确拒绝。
- 影响传播从直接变化出发，只按有语义的方向遍历：符号级 `CALLS/HANDLES` 的调用者，以及文件级 `IMPORTS` 的依赖者。路径、边、证据和预算均绑定具体一侧快照；稳定广度优先搜索返回有限的代表路径，不声称枚举全部路径。预算恰好耗尽但不存在候选余量时不标记截断。
- 左右侧分别记录失败、忽略、秘密、不支持、二进制、超限和子模块清单；顶层完整性汇总无法映射的变化、未知目标和预算截断。部分分析可展示已有证据，但“没有已知影响”不能替代“分析完整”。
- 报告标识包含查询预算；同一捕获内容使用不同深度、路径数或工作量预算时保存为不同报告，不覆盖正在复核的结果。
- 所有结论使用“可能影响”。静态可达、Git 重命名相似度或声明变化都不等于运行时必然执行、语义等价或兼容性破坏。
- 报告与不可变源码持久化；历史报告可继续读取，当前 Git 身份变化则单独标记 stale 并提供重算。

## 安全与性能

- Git 使用参数数组并禁用 external diff、textconv 和 pager；不 checkout、stash、reset，也不执行被分析仓库的脚本。
- 秘密、忽略、符号链接、子模块、二进制、不支持内容和超过 2 MB 的对象不进入源码分析，并保留允许的状态元数据。
- Git blob 先批量查询对象大小，再以最多 64 个对象分块读取，避免逐文件进程启动，同时约束单批内存。
- 后台任务复用版本化 worker 协议，支持进度、取消、失败和重新发起；失败或取消不会保存半成品报告。

## 后果与限制

- 每个比较侧当前仍执行全量分析，优先保证跨文件解析正确；大型仓库成本高于局部分析。
- 报告通过单个持久化 JSON 读取，文件列表在 UI 内分页；超大报告后续应改为数据库行级分页。
- V1 不证明兼容性破坏，不枚举全部路径，不分析子模块内容，也不支持任意两个提交的 UI 选择。
- Windows 无法创建的 Git 合法路径只通过纯解析/对象级测试覆盖；实际工作区路径仍受平台文件系统限制。
- 已排除正文的文件发生内容变化不会使报告过期，因为报告从未读取或分析该正文；分类或路径变化仍会进入状态身份。
