# 架构决策记录 0002：不可变源码快照与后台任务协议

- 状态：已接受并实现
- 日期：2026-09-19

## 背景

证据图如果引用索引时的行列，而源码查看器读取实时工作区，文件一旦变化，旧证据就可能指向另一段代码。长时间索引若运行在 Electron 主事件循环中，也会阻塞界面，并且无法安全取消。

## 决策

1. 每次成功索引都保存源码内容、内容哈希、Graph IR 版本、分析器版本和配置哈希，形成不可变源码快照。
2. 图、解释、题目、答案、源码定位和差异查询都显式携带 `repositoryId` 与 `snapshotId`。
3. 打开证据时显示快照源码，同时重新计算工作区哈希并返回 `current`、`stale` 或 `missing`；不得用实时源码冒充历史证据。
4. 解释、差异和答题等依赖当前工作区的操作在快照过期时拒绝继续；历史证据仍可查看。
5. 新索引在提交前再次读取并核验全部已索引文件。验证失败或取消时不发布新快照。
6. 每个项目使用独立 SQLite 文件。旧共享数据库保留并兼容读取，不删除、不覆盖；旧快照因没有源码副本而标记为 `partial`，需要重新索引后才能使用完整证据导航。
7. Electron 主进程只管理窗口、窄 IPC 和工作线程。索引、TypeScript 分析、Python 子进程与同步 SQLite 写入在独立 Worker Thread 中运行。
8. 后台任务协议使用 Zod 运行时校验并显式版本化，包含任务、根路径、阶段、进度、完成、取消、失败和重试。
9. 分析阶段取消可以终止工作线程；一旦进入短暂的 SQLite 事务提交阶段，事务完成优先，完成事件为最终结果。
10. 新索引任务会取消仍在分析的旧任务；界面只接受当前任务 ID 的事件。旧任务若已进入提交阶段可以完成，但不得覆盖新项目的界面状态。

## 影响

- 历史证据可稳定复核，但源码快照会增加本地磁盘占用。
- 当前实现采用全量重新索引，正确性优先；增量复用需要以后单独证明不会破坏快照一致性。
- 旧版数据库不会丢失，但旧快照没有不可变源码内容，能力明确受限。
- 任务取消不会产生半写快照；提交阶段的取消可能以成功完成结束，这是有意定义的竞态行为。
