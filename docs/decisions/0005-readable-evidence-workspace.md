# ADR 0005：可阅读的证据工作区与分层架构地图

## 状态

已接受并在 V1 实现。

## 背景

固定宽度的图／源码分栏无法兼顾长代码与关系探索；把模块、文件和全部符号同时铺到一张图上也会让真实关系被目录归属淹没。仅替换布局算法不会消除信息过载，还可能把界面分组误当成源码证据。

## 决策

- 图／源码采用可调分栏。分隔条支持指针和键盘，导航可收起，源码可最大化；窄窗口改为显式的图／源码单面板切换。
- 仅在本机保存面板宽度、导航收起和自动换行等纯布局偏好，不保存源码、证据正文或项目凭据。
- Monaco 独立占据标题栏后的剩余高度并管理自身滚动；面板和窗口变化只触发编辑器重新布局，不替换当前文件、快照、选择或证据高亮。
- 架构地图固定为三层：项目目录分组概览、模块内文件、用户选择后的文件／符号局部关系。默认不再把模块连接到全部文件和符号。
- 项目总览的关系图与列表使用同一版本化、有预算的服务端模块概览查询。目录模块必须有真实的模块到文件包含事实；未解析模块引用和外部依赖单独分类，不冒充零文件目录模块。
- 聚合关系是展示对象而不是单条 Graph IR 边；它保存方向、完整统计口径、类型和置信度构成，并通过单独的分页接口打开真实底层边及证据。目录层级只作为界面导航，不生成空证据 ID 的 `verified` 边。
- 文件符号通过服务端精确文件范围、名称、类型和稳定游标查询；浏览器不得先取全局有限结果再按文件过滤。
- 每个异步浏览请求都绑定仓库、快照、层级、选中对象与过滤条件。无法取消的旧请求必须在写入状态前检查身份；返回上层、切换项目和同快照 A→B 导航都会使旧响应失效。
- Cytoscape 实例在组件生命周期内复用。关系上下文变化时替换拓扑并执行有界布局；同一上下文的普通 React 更新和面板尺寸变化不强制 `fit`，从而保留用户视口与选择。首次适应视图只在容器稳定且用户尚未开始交互时执行。
- 没有已打开源码时，证据工作区把全部可用空间交给关系浏览；源码按证据请求展开，可关闭并恢复当前项目的阅读上下文，项目或快照变化时必须清除。
- 节点、边、截断、置信度与未知目标继续遵守 ADR 0003 的快照和证据契约。

## 后果

- 用户可以在图探索和长代码阅读之间调整空间，而无需丢失当前证据上下文。
- 大模块先呈现文件，符号与局部调用按需加载，默认画布规模受层级和既有查询预算共同约束。
- 模块总览默认只展示当前有界模块页内的聚合关系；跨页关系需继续浏览，界面必须显示当前范围和截断，而不能把当前页称为完整仓库图。
- 关系缺失时界面明确说明没有证据，不用视觉连线补写架构。
- 当前布局偏好是浏览器配置级而非项目级；多显示器和除实测环境外的显示缩放仍需后续覆盖。

## 2026-09-22 实现补充

架构会话为最多 40 个快照/查询上下文保留画布缩放、平移、节点位置与选择；首次异步加载和拓扑变化与普通面板 resize 分开处理。层级切换返回导航，源码上下文仍可显式恢复。真实关系先通过证据检查面板读取并核验快照与证据 ID，再由用户定位源码；面板取消和切换使旧读取失效。以上均为界面状态，不新增 Graph IR 事实或远程数据传输。
